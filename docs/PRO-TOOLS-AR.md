# أدوات احترافية لإدارة MikroTik

## 1) فحص الأمان `GET /api/routers/:id/security-audit`
قراءة فقط. يفحص: Telnet/FTP/HTTP، API غير المشفر، WinBox/SSH/API-SSL المفتوحة لكل العناوين، غياب drop على سلسلة input، DNS المفتوح، اكتشاف الجوار وMAC-server، المستخدم admin الافتراضي، تشفير SSH، إصدار RouterOS 6، ودخول HotSpot عبر http-pap.
- النتيجة: `score` من 100 و`grade` (A-F) و`findings` مع `fix`.
- `fixScript` يحوي فقط الإصلاحات الآمنة (مثل تعطيل telnet/ftp). الإصلاحات التي تحتاج بيانات منك (`<YOUR-ADMIN-IP/32>`) أو قد تقطع الاتصال (الجدار الناري، API الذي يستخدمه التطبيق) **لا تُنفَّذ تلقائياً** وتظهر كقوالب للمراجعة.
- لا يعمل على راوتر Agent (يعيد `ROUTER_IS_AGENT_MODE`).

## 2) لوحة الأسطول `GET /api/fleet[?probe=1]`
حالة كل راوتر (online/offline/pending/unknown)، عدد المستخدمين النشطين، متوسط CPU، وقائمة «يحتاج انتباه» (انقطاع أو CPU ≥ 85%). `probe=1` يفحص منفذ الراوترات المباشرة (حتى 30).

## 3) تنبيهات الانقطاع التلقائية
مراقب في السيرفر كل دقيقة: إذا لم يتصل راوتر Agent أكثر من 5 دقائق يُنشأ إشعار «غير متصل» مرة واحدة، وعند عودته إشعار «عاد للاتصال».

## 4) مشخّص الإعدادات `GET /api/system/doctor` (أدمن)
يفحص قوة الأسرار، CORS، `PUBLIC_BASE_URL`، `TRUST_PROXY`، فتح التسجيل، تعطيل التحقق من الشهادات، مفاتيح الدفع، واتصال قاعدة البيانات.

## توصيات لم تُنفَّذ بعد
- نموذج فريق حقيقي (موظفون يشاركون رواتر الأدمن): يتطلب تغيير نطاق الاستعلامات من `user_id` إلى معرّف الحساب/المنظمة.
- إبطال JWT وقفل الحساب بعد المحاولات الفاشلة.
- نسخ احتياطي مجدول لإعدادات الراوتر (`/export`).
- شاشات Android للوحة الأسطول وفحص الأمان والتحليلات.
