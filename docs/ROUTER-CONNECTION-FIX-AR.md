# إصلاح اتصال RouterOS في MICRO-MAX

## ما تم إصلاحه

أضيف طابور تسلسلي داخل `backend/src/routeros.js` حتى لا تُرسل أوامر متعددة على نفس اتصال RouterOS في الوقت نفسه. بروتوكول RouterOS API لا يضع رقم طلب مستقلًا لكل رد، لذلك تداخل الأوامر قد يؤدي إلى قراءة رد أمر على أنه رد أمر آخر.

هذا الإصلاح مهم لمسارات مثل:

- قراءة المستخدمين والجلسات بالتوازي.
- قراءة خريطة الشبكة.
- فحص الموارد والواجهات والـDHCP.
- اختبار API وAPI-SSL.
- توليد الكروت مع أكثر من استعلام على نفس الجلسة.

## التحقق

تم تشغيل اختبارات Backend بنجاح:

- `62` اختبارًا ناجحًا.
- اختبار جديد للطلبات المتزامنة على اتصال RouterOS واحد.
- فحص صياغة JavaScript لطبقة RouterOS وNetwork Guard.
- لم يتم تنفيذ أي أمر تغييري على راوتر حقيقي.

## إعدادات الاتصال

### Agent للراوتر خلف NAT

استخدم مسار Agent. لا يحتاج فتح منفذ وارد، ويحتاج الراوتر إلى DNS وإنترنت ووقت صحيح.

### API محلي من الهاتف

استخدم `8728` عندما يكون الهاتف على نفس شبكة الراوتر، مثل `192.168.88.1`.

### API-SSL عن بعد

استخدم `8729` مع TLS وشهادة صحيحة، ويفضل تثبيت بصمة SHA-256 للشهادة. لا تستخدم عنوانًا داخليًا مع Backend مستضاف على Render.

## نشر Backend

1. انسخ الملفات من مجلد `backend` إلى مستودع Backend المنشور على Render.
2. نفذ:

```bash
npm ci
npm test
node --check src/routeros.js
```

3. ادفع التغيير إلى الفرع المرتبط بخدمة Render.
4. انتظر اكتمال النشر.
5. تحقق من:

```bash
curl -fsS https://micro-max-api.onrender.com/health
```

يجب أن تكون النتيجة شبيهة بـ:

```json
{"ok":true,"service":"MICRO-MAX API","version":"2.0.0"}
```

## ملاحظات أمان

- لا تستخدم `full` لحساب Agent.
- لا تضع كلمات المرور أو `JWT_SECRET` داخل المستودع.
- لا تفتح `8728` أو `8729` للعالم إلا عند الحاجة.
- استخدم Agent للراوترات المحلية أو الموجودة خلف NAT.
- لا يتم تشغيل إصلاحات على الراوتر تلقائيًا من هذا التعديل.

## v12.2 — إصلاح الاتصال من الموقع
1. **Dockerfile**: كان لا ينسخ مجلد `public` فلا يظهر الموقع على Render. أضيف `COPY public ./public` (يلزم إعادة النشر).
2. **نافذة Agent**: كانت تُغلق فور إنشاء السكربت فلا يمكن نسخه. أصلحت، وأضيفت حالة حية: «⏳ بانتظار أول اتصال» ثم «✔ الراوتر متصل»، ورسالة تشخيص إن لم يتصل خلال دقيقتين.
3. **الاتصال المباشر**: تحذير تلقائي عند كتابة عنوان داخلي (مثل 90.50.50.1 أو 192.168.x.x) مع زر «التبديل إلى Agent»، ورسالة خطأ توضح أن الخادم السحابي لا يصل للعنوان.
4. مصمم الكروت `/designer.html` مع الطباعة المباشرة.

القاعدة: العنوان الذي تفتح به Winbox من واي فاي الراوتر = عنوان داخلي ⇒ استخدم Agent.

## v12.3 — اتصال التطبيق عبر شبكة الواي فاي (ECONNREFUSED مع أن API مفعّل)
عندما يكون واي فاي الراوتر بلا إنترنت، قد يرسل أندرويد اتصالات التطبيق عبر بيانات الجوال. العنوان 90.50.50.1 هو عنوان عام في الإنترنت أيضاً، فيصل الطلب إلى جهة أخرى ترفض المنفذ 8728. WinBox وتطبيقات أخرى تربط الاتصال بشبكة الواي فاي صراحة. التطبيق الآن يربط المقبس (Socket) بشبكة Wi-Fi أولاً (API و API-SSL) ثم يعود للمسار الافتراضي عند الفشل. حل فوري بدون تحديث: أوقف بيانات الجوال أثناء الإضافة.

## v12.4 — تقرير الاتصال داخل التطبيق
عند فشل الاتصال يعرض التطبيق تقريراً (بدون كلمات مرور): نوع الشبكة الافتراضية للهاتف، عنوان الهاتف وبوابة الواي فاي (عنوان الراوتر الحقيقي)، وهل المنفذ يُفتح عبر Wi-Fi مباشرة وعبر المسار الافتراضي مع اسم الخطأ.
