# ربط الراوتر بـ MICRO-MAX (محلي / عن بعد)

الهاتف لا يتصل بالراوتر. **الـ Backend** هو الذي يصل إليه. وخادم Render سحابي لا يستطيع الوصول إلى `192.168.x.x`، لذلك توجد ثلاث طرق:

| الحالة | الطريقة | يحتاج فتح منفذ؟ |
|---|---|---|
| راوتر خلف NAT / IP متغير / عن بعد | **Agent** (الأفضل) | لا |
| راوتر بعنوان عام ثابت | **API-SSL** + تثبيت الشهادة | نعم، 8729 مع قائمة سماح |
| Backend على جهاز داخل نفس الشبكة | اتصال مباشر (API/API-SSL) | لا |

## 1) وضع Agent (موصى به)
1. اضبط على السيرفر: `PUBLIC_BASE_URL=https://micro-max-api.onrender.com`.
2. `POST /api/routers/agent/enroll` مع `{"name":"اسم الفرع"}` يعيد `script`.
3. الصق السكربت في Winbox ← New Terminal. الراوتر يتصل بالسيرفر كل 30 ثانية ويظهر متصلاً خلال دقيقة (`GET /api/routers/:id/agent/status`).
4. متطلبات الراوتر: RouterOS 6.49+ أو 7.x، DNS يعمل، وتاريخ/وقت صحيح (NTP) للتحقق من الشهادة.
5. توليد الكروت يتم على السيرفر ثم تُرسل إلى الراوتر كمهام (`hotspot-user-add`). الكرت يبقى `provision_state=pending` ولا يمكن بيعه حتى يؤكد الراوتر الإنشاء (`ready`).
6. فقدان السكربت أو تسريب الرمز: `POST /api/routers/:id/agent/rotate` يُبطل الرمز القديم.

الأمان: لا يُنفَّذ على الراوتر إلا نوعان من الأوامر (إضافة/حذف مستخدم HotSpot)، وكل قيمة تُفحص بقائمة أحرف صارمة، والرمز يُخزَّن مجزّأ (SHA-256) فقط.

6. **البروفايلات:** `POST /api/routers/:id/hotspot-profiles` ينشئ بروفايل HotSpot حقيقياً على MikroTik عبر الـ Agent (إضافة أو تعديل بدون تكرار). الحالة `provisionState` تصبح `ready` بعد تأكيد الراوتر.

**غير مدعوم في وضع Agent حالياً:** لوحة المعلومات الحية، الطرفية، محرر صفحات HotSpot، مطابقة الكروت. هذه تعرض الخطأ `ROUTER_IS_AGENT_MODE`.

## 2) وضع API-SSL
1. `POST /api/routers/direct-setup` (أدمن) مع `{"allowFrom":["IP_السيرفر"]}`. خذ عناوين الخروج (Outbound IPs) من لوحة Render.
2. شغّل السكربت الناتج على الراوتر: ينشئ شهادة، يفعّل API-SSL على 8729، يعطل API العادي، ينشئ مستخدماً بصلاحيات محدودة، ويضيف قاعدة جدار ناري، ثم يطبع **fingerprint**.
3. أضف الراوتر بـ `POST /api/routers` مع `tls:true` و`port:8729` و`fingerprint`. الاتصال يُثبَّت على بصمة الشهادة، فلا حاجة لـ `ALLOW_INSECURE_ROUTER_TLS`.

## 3) تشغيل محلي
شغّل Docker على جهاز في نفس شبكة الراوتر، واضبط `ALLOW_PRIVATE_ROUTER_HOSTS=true`. عندها يعمل البحث التلقائي `/api/routers/discover` والاتصال بعناوين خاصة.

## تغييرات سلوك مهمة
- العناوين الخاصة (`192.168.x.x`...) مرفوضة افتراضياً على السيرفر السحابي. الراوترات القديمة المسجلة بعناوين خاصة تحتاج `ALLOW_PRIVATE_ROUTER_HOSTS=true` أو تحويلها إلى Agent.
- المنافذ المسموحة افتراضياً 8728 و8729 فقط (`ROUTER_ALLOWED_PORTS`).
- عناوين loopback و169.254.x.x (metadata) مرفوضة دائماً.

## جلب بروفايلات MikroTik وتوليد الكروت منها
1. `POST /api/routers/:id/hotspot-profiles/import` يقرأ بروفايلات HotSpot الموجودة فعلاً على الراوتر (السرعة، المدة، الأجهزة) ويحفظها، ولا يغيّر السعر الذي حددته. في راوتر Agent يستخدم أسماء البروفايلات التي يرسلها الراوتر مع كل اتصال (أعد تشغيل سكربت `rotate` مرة واحدة ليرسلها).
2. كل بروفايل يعود مع `planId` و`readyForCards`. إن كانت `false` أنشئ له باقة وسعراً عبر `POST /api/routers/:id/plans`.
3. ولّد حتى 5000 كرت في الطلب الواحد عبر `cards/generate`. في وضع Agent تُرسل الكروت على دفعات (25 كرت لكل تأكيد، حتى 300 لكل اتصال)، فتكتمل 5000 كرت خلال حوالي 10 دقائق، وتبقى الكروت `pending` حتى يؤكدها الراوتر.

## الخادم الحالي
`https://micro-max-api.onrender.com` (مضبوط افتراضياً في التطبيق وفي `.env.example`). اضبط في Render ← Environment: `PUBLIC_BASE_URL=https://micro-max-api.onrender.com`.

## لماذا كان الاتصال يفشل
1. **خادم Render لا يصل إلى `192.168.x.x`**: عناوين الشبكة المحلية غير قابلة للوصول من الإنترنت. الحل: Agent (لا يحتاج فتح منافذ).
2. **الخطة المجانية تنام**: أول طلب بعد خمول قد يستغرق حوالي دقيقة. التطبيق الآن يوقظ الخادم عبر `/health` قبل الطلبات (مهلة حتى 75 ثانية).
3. **مهلات قصيرة**: كانت مهلة الطلب 30 ثانية، فتفشل دفعات الكروت الكبيرة. أصبحت 120 ثانية.
4. **حد الطلبات**: كل الطلبات كانت تُحسب من عنوان الـ Proxy نفسه إن لم يُضبط `TRUST_PROXY`، وكانت اتصالات الـ Agent تُحسب ضمن الحد العام. أصبح الـ Proxy موثوقاً تلقائياً على Render، واتصالات الـ Agent لها حد خاص.
5. **رسائل خطأ غير واضحة**: أضيفت رسائل عربية للأخطاء الشائعة (عنوان غير مسموح، منفذ، بصمة الشهادة، نوم الخادم).

## في التطبيق
إضافة راوتر ← شاشة اختيار: **Agent (موصى به)** / عنوان عام API-SSL / شبكة محلية. في Agent: تنسخ السكربت، تلصقه في WinBox، وتظهر الحالة «متصل» تلقائياً.

## الربط التلقائي بدون نسخ (الأسرع)
1. اتصل بواي فاي الراوتر.  2. إضافة راوتر ← «ربط تلقائي».  3. أدخل الاسم والمستخدم (admin) وكلمة المرور، واضغط «ربط الآن».
التطبيق يكتشف عنوان الراوتر، ويتصل به من الهاتف مباشرة عبر RouterOS API (8728)، ويثبّت شهادات الـ CA وسكربت الـ Agent والمجدول، ثم ينتظر أول اتصال ويجلب البروفايلات تلقائياً. بيانات دخول الراوتر لا تُرسل للخادم.
المتطلبات: خدمة API مفعلة في الراوتر (IP ← Services، وهي مفعلة افتراضياً)، والراوتر متصل بالإنترنت، وRouterOS 6.43 أو أحدث. بعد الربط يعمل الراوتر من أي مكان.
