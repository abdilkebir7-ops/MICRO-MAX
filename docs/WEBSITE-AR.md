# موقع MICRO-MAX (v12)

يُقدَّم الموقع من نفس خادم الـ API: افتح `https://micro-max-api.onrender.com/` بعد النشر.

## الصفحات
| الصفحة | الوظيفة |
|---|---|
| `/` | الرئيسية + أحدث القوالب + أحدث إصدار |
| `/login.html` | دخول / حساب جديد (+ Google إن فُعّل) |
| `/console.html` | **لوحة تحكم بأسلوب Winbox**: نوافذ عائمة، 19 قائمة RouterOS (عرض/إضافة/تعديل/تعطيل/حذف)، Dashboard حيّ، Terminal، توليد وطباعة الكروت (QR محلي)، نشر قوالب Login، المبيعات، فحص الأمان |
| `/store.html` | متجر 12 قالباً + قوالب المدير، معاينة/تحميل/نشر على الراوتر |
| `/builder.html` | منشئ قوالب مرئي (ألوان، تخطيط، باقات، واتساب، PIN) مع تحقق MikroTik |
| `/download.html` | تحميل APK + سجل الإصدارات + `SHA-256` |
| `/admin.html` | المدير: إحصائيات، مستخدمون (دور/تعطيل)، قوالب المتجر، إصدارات، إعلانات، سجل التدقيق |

## المدير
البريد `abdilkebir7@gmail.com` هو المدير (يمكن تغييره بالمتغير `ADMIN_EMAILS` مفصولاً بفواصل).
لأن التسجيل بكلمة مرور لا يتحقق من ملكية البريد، حساب المدير يُنشأ بإحدى طريقتين:
1. **Google Sign-In** (البريد موثّق من Google) — تلقائي.
2. التسجيل بكلمة مرور **مع مفتاح الإعداد**: اضبط `ADMIN_SETUP_KEY` (12 حرفاً على الأقل) في Render، ثم عند التسجيل بهذا البريد يظهر حقل المفتاح.
إن كان الحساب موجوداً مسبقاً بهذا البريد فيُرقّى إلى admin عند أول دخول.

## التحديثات
- ارفع APK إلى GitHub Releases (الـ workflow `release-apk.yml` يفعل ذلك عند دفع وسم `v*`) وسجّله من `/admin.html ← الإصدارات` (أو تلقائياً بأسرار `MICROMAX_ADMIN_EMAIL/PASSWORD`).
- `/download/latest` يحوّل لأحدث APK. `GET /api/site/update-check?current=3.1.0` يعيد `updateAvailable` ليستخدمه التطبيق.

## واجهات جديدة
`/api/site/*` (عامة)، `/api/admin/*` (admin فقط)، `/api/menus` و`/api/routers/:id/menu/:key[/:action]` (قائمة بيضاء صارمة، الكتابة للمالك/المدير وتُسجَّل في التدقيق).

## ملاحظات أمان
- المعاينات تُخدَّم بـ `CSP: sandbox` ولا تنفذ نماذج.
- تعطيل مستخدم أو تغيير دوره يسري فوراً (يُتحقق منه من القاعدة بكاش 15 ثانية).
- أوامر RouterOS في القوائم تُبنى من مخطط ثابت؛ المعرّفات تُتحقق (`*1A`) والقيم بلا أسطر/رموز تحكم.
